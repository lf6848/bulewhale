# 三层记忆结构设计 v2（日记 / 自我 / 事实）

> 状态：自我层与读路径已上线（v0.2.0，2026-10-29 18:51 验证）。长期记忆 v2 仍在影子/灰度。
> v2 相对 v1 的改动集中在四件事：**自我该写什么、修订的约定、日记的选材、权限与公式对齐 v4**。

---

## 1. 三层分工

| 层 | 是什么 | 存哪 | 何时写 | 何时读 | 预算 |
|---|---|---|---|---|---|
| **日记** | 叙事：今天发生了什么、情绪、没想通的事 | `astrbot_brain/diary/<日期>.md` + `diary_index.json` | 每天 04:40 | 问题指向某天/某主题时 | 300 字（追问细节可 800） |
| **自我** | 人格：身份、脾气、相处方式、近期关注 | `astrbot_brain/self.md` + `self_history/` + `self_log.json` | 每天 04:40，且**允许不改** | **每轮**（system prompt） | 205 字（上限 700） |
| **事实** | 离散断言：养了鸡、在上海上学 | `memory_system.db.memories` | 对话后自动抽取 | 三路召回注入 | ≤5 条 / 320 token |

**分工口诀：事实是词汇，日记是句子，自我是口吻。**

### 1.1 什么进哪一层（v1 的错误就在这）

| 材料 | 去处 | 理由 |
|---|---|---|
| 具体的人、具体的事（谁请吃饭、谁连败） | 日记 + 事实 | 一次性，跨天复述只会让每条回复都被昨天拽住 |
| 一段时间的兴趣（味觉交互器、某场比赛） | 自我里的【近期关注】，**带日期、允许退出** | 有生命周期，两周不再提就删 |
| 反复出现的相处方式（≥2 个场合，或被明确纠正） | 自我里的【我和他们怎么相处】 | 这才叫性格，能指导下一次说话 |
| 身份与基本边界 | persona +【我是谁】 | 稳定，改动要人来做 |

示例（用户给的范式，已写进提示词）：

```
日记：今天这个玩笑没被接住，下次先看他的状态。
相处偏好：对翔仔——他认真或低落时，收住战绩玩笑。
多次验证后 → 自我：我喜欢和熟人互损，也会留意什么时候该收住。
```

> 反例：首版自我里写的「达美乐、翔仔连败三把、味觉交互器、战绩旧账」——这些是**经历**，不是性格。已从自我移出（见 §3.2）。

## 2. 数据流

```
平台消息 data_v4.db（含用户发言 + 大肥鱼自己的回复）
        │
        ▼  每天 04:40（宿主机 cron）
 /usr/local/bin/brain-night.py
   ① 取窗口：处理「刚结束的那一天」00:00–23:59（TZ+8）
   ② 写日记 → diary/<日期>.md + 索引一行（三段可空、情绪可无）
   ③ 修订自我 → self.md（旧版进 self_history/；无改动就不写）
        │
        ▼  每个 LLM 请求（容器内插件）
 astrbot_brain_read v0.2.0
   · self.md            → req.system_prompt（每轮，按天稳定）
   · 日记（按天/主题选材）→ req.prompt 末尾（仅时间类问题）
 astrbot_memory_shadow（v2 灰度）
   · 事实召回            → req.prompt 末尾
```

### 2.1 夜间输入确实包含"我自己说了什么"

`brain-night.py` 的 `seg_text()` 只接受 `content.type in ("user","bot")`，`bot` 行渲染成「我：…」，`user` 行渲染成「昵称：…」。所以日记能看到「我怎么回的、对方什么反应」，不是单边记录。

**已知缺口**：目前没有结构化保存"这句回复收到了什么反馈"（被点赞/被无视/被纠正），只能靠全文推断。若要做「效果评估」，需要在 `platform_message_history` 之外补一张「回复-反馈」配对表。

### 2.2 位置与缓存

- **self 放 system prompt**：一天之内不变 ⇒ 前缀稳定。
- **日记与事实放 prompt 末尾**：每轮可能变，只让末段失效。
- **验证方式改为实测**：不再用"放 system 就命中"这种推断，改用 DeepSeek 返回的 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 核算；已知那是尽力而为，不是保证。

### 2.3 预算（实测，2026-10-29 18:51）

| 块 | 字符 | 约 token | 触发 |
|---|---|---|---|
| self.md | 205 | ~110 | 每轮 |
| 日记块 | 466（正文 300） | ~250 | 仅时间类问题 |
| 展开模式（问细节） | ≤ 800 正文 | ~450 | 含"复盘/详细/发生了什么" |

## 3. 自我层

### 3.1 结构（v2 改）

```
【我是谁】      身份，极少变
【我的脾气】    稳定的说话方式与价值观
【我和他们怎么相处】 对具体某人的、反复验证过的相处方式
【近期关注】    最近在意的事，每条带（YYYY-MM-DD），两周不再提自动删
```

### 3.2 修订约定（写死在提示词 + 程序里）

1. **允许零修改**：今天没有值得沉淀的，原样输出。程序比较前后版本，无差异就不重写文件，`self_log` 记 `changed:false`。
2. **证据分级**：具体事件不进自我；一时兴趣只能进【近期关注】；只有反复出现的相处方式/偏好才能进脾气与相处方式。
3. **纠正优先级**：对方明确纠正（"今天别损我"）→ 立刻改对该人的一行；全局脾气慢改，不因一句话改性格。
4. **同一段聊天只算一份依据**：日记、索引、事实重复提到同一件事，不因重复而加重。
5. **昨天的自我不是证据**：它是延续背景，不能因为"昨天这么写"就更确信。
6. **CHANGES 只是解释**：真实改动范围由 `diff_lines(old, new)` 逐行比较得出，模型说"无"也可能改了（首版就出现过：`changes:"无"` 但实际 +4/-4 行）。

程序侧强制：`prune_recent()` 删除超过 14 天的【近期关注】条目，并截断到 3 条。

### 3.3 与 persona 的边界

- persona 管**身份与边界**（我是谁、不能做什么），self 管**风格与发展**（怎么说话、怎么对人）。
- 不靠"谁排在前面"实现优先级；**明确 self 可以改哪些字段**：只能改【我的脾气】【我和他们怎么相处】【近期关注】，不能改【我是谁】。
- 若 persona 写得过死（如"无论何时都怼人"），应由人改为"默认倾向"，**自动生成的 self 不承担修改基本规则的职责**。

## 4. 日记层

### 4.1 写入

- 输入：当天消息（最多 40 条，超大时等距抽样）+ 当天新写入的事实
- 结构性要求：三段标题固定，但**允许不足或为空**；情绪可以写"没什么明显变化"，避免为格式编悬念
- 抽样规则（待实现）：纠正、承诺、明确反馈所在的消息优先保留上下文，不被抽样丢掉
- 保护：无对话无记忆 → 不写空日记；失败只记 `errors.log`

### 4.2 读取（v2 从"看到时间词"升级为"找到对应经历"）

| 问法 | 选材 |
|---|---|
| 昨天/昨晚/前天 | 那一天（缺则退回最近一篇） |
| 上周 | 上周一整周（没有就**不注入**，不硬凑） |
| N 天前 | 那一天 |
| 记得…住哪/叫什么/几岁 | **不注入**，交给事实层 |
| 原话/承诺/答应了什么 | **不注入**，交给 short_recall 取原始消息 |
| 之前那个味觉交互器 | 用索引做主题匹配，取相关日期 |

- 标题一律用**真实日期**：`【2026-10-29 的日记】`，不会把三天前的写成"昨天"。
- 命中不了就返回空 —— 宁缺毋滥。

## 5. 权限（对齐 v4）

- **默认不跨范围共享**：`private_only=true`、`cross_scope_share=false`。私聊里学到的具体事实，默认不在群里出现。
- 用户明确说"这个可以跟别人讲" → 只放开那一条（`allow_groups` 白名单），可撤销。
- **日记与自我同样继承来源权限**，不是"公开展示物"。
- 权限过滤在**候选检索之前**做（已在生产库验证：收紧 `private_only`/`deleted_at` 后下一轮立即不注入，无需 scrub）。
- 【我在意的人/相处方式】里的具体名字与事件**按当前对话范围加载**；全局 self 只放稳定风格，关系细节按对象与范围取。
- 文本里不展示编号与分数，但后台保留来源（`source_msg_ids`）与权限。

> **当前实现的缺口（诚实标注）**：self.md 仍是一个全局文件，整体注入；虽然已把具体事件移出，但"对某人的相处方式"仍是全局文本。要实现"按对象/范围加载"，需要把关系段拆成 `relations/<user_id>.md` 并在注入时按当前 `sender_id` 与权限过滤 —— 列为下一步。

## 6. 公式（对齐 v4）

时间常数 `S` 一经定义为"衰减时间常数"，就必须用指数式：

```
R = exp(-age / S)          # 半衰期 = S·ln2
```

v1 稿里的 `0.5^(age/S)` 会让 `S` 变成"半衰期"，语义不一致，已废弃。

## 7. 运行与检查

- **04:40 的定义**：处理"刚结束的那一天"（TZ+8 的 00:00–23:59），与 04:05 容器重启、04:30 快照错开。
- **补写历史日记默认只补档**：`--date` 指定过去日期时**不修订自我**（避免把旧材料当成今天的新经历），需要时显式 `--force-self`。
- **观察期（一周）三件事**：①每次自我改动都能追到新依据（`self_log.added/removed`）②改动在**新情境**里真的表现出来 ③收到明确反馈后，下一次是否调整。
- **什么算"性格成长"**：记得共同经历、有稳定的表达偏好、对熟人形成不同相处方式、被纠正后能改——按这些可观察行为验收，而不是"每天 self 都有新内容"。
