## 1. 字段与三个时钟

| 字段 | 含义 | 备注 |
|---|---|---|
| `event_at` | 事情**发生**时间 | 只描述发生，**永不**用作衰减基准 |
| `created_at` | 入库/观察时间 | 旧数据回填的唯一默认值 |
| `last_reinforced_at` | 最后一次**有效证据**时间 | 衰减基准；初始化 = `created_at` |
| `last_accessed_at` | 最后被注入时间 | 仅统计 |
| `initial_strength_s` | 创建时冻结的 S0（秒） | 防参数漂移 |
| `fact_mode` | `state` / `event` | 状态型 vs 一次性事件 |
| `valid_from` / `valid_to` | 状态成立区间（null=至今） | 仅 `state` |
| `occurrence_at` | 单次发生时间 | 仅 `event` |

约定：
- 全表 epoch 秒；`age = max(0, now - last_reinforced_at)`。
- **回填**：`last_reinforced_at = created_at`（不再用 `COALESCE(event_at, …)`）。仅当存在可靠的历史确认消息（当时确实重提过）时，才用那条消息的时间。理由：今天第一次听到"我十年前养过猫"，记忆年龄从今天起算。
- 存储用 UTC；"昨天""上周"的**自然日边界**按用户/群配置时区（默认 `Asia/Shanghai`）计算，不用 UTC 日界。

## 2. 状态机

### 2.1 记录状态

```
active ──被证伪/被替代──> superseded ──撤销──> active
   │
   ├─冲突无法裁决──> uncertain ──确认──> active / superseded
   └─同义合并（人工批准）──> merged（派生，原条保留）
```

`superseded` / `uncertain` 正文永不改写；可检索，但默认不注入。

### 2.2 冷层：查询时派生，且**只由 R 与 pinned 决定**

```
is_cold = (R < 0.08) and status == 'active' and not pinned
```

- **取消** v3 的 `importance < 0.75` 豁免：它与"确认后 importance≥0.85"直接矛盾，会让确认过的事实永久免降级。
- importance 只影响 S0（衰减快慢）与注入排序，**不产生永久保护**；永久保留只能由 `pinned` 显式表达。
- **S0 冻结语义**：创建后调整 importance **不重算** `initial_strength_s`（否则改参数等于偷偷改历史）。唯一例外：用户明确说"这件事很重要／永远记住"时，允许一次受审计的 `strength_readjust` 事件重算，并在 `memory_events` 里留下 before/after。
- 冷层不是"遗忘/删除"，而是**提高召回门槛**：`rel ≥ 0.20` 才注入，且最多 1 个名额。R 再低，强线索仍可召回。
- 升回：只有新证据（REPEAT）能提升 `recall_count` → S 重算 → R 回升。时间本身不会升温。
- `cold_due_at = last_reinforced_at + S·ln(1/0.08)` 仅作观测值，不落库、不参与查询。

### 2.3 REPEAT 与 UPDATE 的语义（v3 自相矛盾处）

| 判定 | 作用对象 | 计数 |
|---|---|---|
| `REPEAT` | **原记录** | `recall_count + 1`、`last_reinforced_at = now` |
| `UPDATE` | **新建版本** | 新记录 `recall_count = 0`、`last_reinforced_at = created_at`；旧记录转 `superseded` 并保留历史 |

`UPDATE` 不是强化，旧记录也不会因为"被更新"而获得强度。

### 2.4 用户"确认"到底改变什么

确认**不改变初值**，只改变证据：

| 情况 | 处理 |
|---|---|
| 首次明确陈述 | 建记录，保存原话来源，`recall_count=0`，S0 由 importance 决定 |
| 再次明确确认同一事实 | 更新确认依据（`source_msg_ids`），按窗口/去重规则**强化一次**（`recall_count+1`） |
| 用户强调"这件事很重要" | 单独评估 importance（可经审计事件重算 S0） |
| 用户明确要求"永远记住" | 置可撤销的 `pinned`（不改强度，只免于冷层压制） |

确认只说明"这条自述有直接依据"，**不说明它值得长期保留**——"对，我昨天中午吃了面"确认得再明确，长期价值依然很低。

## 3. 公式与"多久进冷层"

```
S0_s = max(2 天, 0.75 天 · exp(3.2 · importance)) · 86400     # 创建时冻结
S(n) = min(173 天, S0 · (1 + 1.2 · ln(1 + n)))                # n = recall_count
R    = exp( -(now - last_reinforced_at) / S )
cold ⇔ R < 0.08 ⇔ Δt > 2.526 · S
```

| importance | S0（天） | 未强化进冷层 | REPEAT 一次后 |
|---|---|---|---|
| 0.5 | 3.72 | 9.38 天 | 17.2 天 |
| 0.85 | 11.38 | 28.7 天 | 52.6 天 |
| 0.9 | 13.36 | 33.7 天 | 61.7 天 |

表述订正：**"9 天后不再默认注入、召回门槛提高"**，不是"忘了"。上限 `H_max=120 天`（`S_max=173 天`）同理，只是门槛最高。

## 4. 抽取：按**事实操作**输出，不是按消息

一条消息可产出 0～n 个操作，也可能是"无可记录事实"：

```json
{"ops":[
  {"op":"NEW",     "fact":{...}, "confidence":0.9},
  {"op":"REPEAT",  "target_id":123, "evidence":"原话片段"},
  {"op":"UPDATE",  "target_id":124, "fact":{...}, "reason":"住址变更"},
  {"op":"UNCERTAIN","target_id":125,"fact":{...},"conflict":"与 10-22 的说法相反"}
]}
```

### 4.1 事实身份

- `fact_key = sha1(subject_id|attribute|normalized_value)` **只用于候选检索**，不能作为"必须相等"的判定条件。
- 认定 REPEAT 还要核实：同 `subject_id`、同属性、值等价、同极性（否定另算）、时间相容。
- **事件型不适用 REPEAT**：`"昨天吃面"` 与 `"今天吃面"` 是两次不同经历，各建 `event` 记录（`occurrence_at` 不同）。若模型想表达"常吃面"，那是另一条 `preference`/habit 事实。

### 4.2 幂等

- `processed_messages(message_id PRIMARY KEY, window_id, ts, result)`：整条消息只处理一次。
- `reinforce_events(memory_id, window_id, source_msg_id, UNIQUE(memory_id, window_id))`：**同一记忆、同一窗口最多强化一次**（窗口 = `umo + 30 分钟桶` 的稳定哈希）。
- 计数与时间在同一事务内更新。
- 不产生强化：问句、假设、引用他人、否定（否定走 UPDATE 或反向事实）、日记/摘要自产内容。

## 5. 冲突、替代与 pinned

替代需同时满足：同 `subject_id`、同**属性**、`state` 型且 `valid_from` 区间与旧值重叠、新值**否定/更新**旧值。

- 状态型替代：旧 `valid_to = 新 valid_from`，旧 `superseded_by = 新 id`，新 `supersedes_id = 旧 id`。
- 历史陈述不替代当前状态：`"三年前我住北京"` 是 `valid_from..valid_to` 的闭区间历史，`"我现在住上海"` 的区间覆盖至今。
- **pinned 可被纠正**：pinned 只保护"保留策略"（不被裁掉、不被冷层压制），不保护错误内容；替代 pinned 记录允许，但需 `pinned_corrected` 事件留痕。
- 程序校验（LLM 给旧 id 之后）：归属同一 user、可见域允许、不是 summary、`subject_id` 一致。
- 裁决不了 → 双向 `uncertain`；**注入时两条作为一个整体**，预算不够则两条都不注入，不允许只留一条。

## 6. 召回

### 6.1 先判查询类型（这一步决定 rel 怎么算）

| 类型 | 例 | 结构化命中的地位 |
|---|---|---|
| 定向（targeted） | "我学什么专业""我住哪" | 主体命中只是**必要条件**，还必须命中所问属性/主题；时间仅作过滤 |
| 泛问（broad） | "你知道小明哪些事""昨天发生了什么" | 人物或时间**可单独**构成强相关 |

实现：一次低成本意图判定（规则优先：「哪些事/都/发生了什么」→ broad；含具体属性词 → targeted），判不出发
LLM 一次；判失败按 targeted 保守处理。

### 6.2 rel

```
targeted:  rel = 0.6·text_sim + 0.4·attr_match        （attr 不匹配则 rel ≤ 0.15）
           subject_hit 只给 +0.10，不作为主项
broad:     rel = max(text_sim, 0.85·subject_hit, 0.75·time_hit)
```

这样"我学什么专业"不会让所有关于"我"的事实都拿到 0.85，也就不会同时越过 cold 门槛。

### 6.3 两阶段

```
候选：A 关键词 ≤24 / B 人物 ≤8 / C 时间 ≤8（宽进，可重叠）
→ 合并去重（保留路径标签）
→ 计算 rel → 过滤 rel<0.05（cold 需 ≥0.20）
→ 冗余去除（**先评分再决定保留哪条**；同 fact_key 或相似度>0.9 时保留分数高者；
   历史版本与冲突记录**不参与**相似度去重）
→ 贪心按 token 预算取，≤5 条
→ B/C 保底名额仅在**已通过相关性筛选**的候选里分配
→ 最近 24h 兜底占 1 个名额，计入总数
```

## 7. 夜间任务

| 任务 | 范围 | LLM |
|---|---|---|
| 生成 brief / 主题词 / 重算 fact_key | 仅新增或内容变更 | 是 |
| 计算 `cold_due_at` 观测值 | **全表**纯算术 | 否 |

| 日记 / 自我修订 | 当天窗口 | 是 |

夜间不写 `recall_count` / `last_reinforced_at`；影子期间主题词写影子列，**不改线上 tags**。

## 8. 权限模型（三方分离）

| 维度 | 字段 | 作用 |
|---|---|---|
| 谁提供 | `owner_id` | 来源与追责 |
| 说的是谁 | `subject_id` / `about_user_id` | **仅用于检索**，不授予任何可见性 |
| 允许在哪用 | `visibility` + `allow_groups` | 唯一授权来源 |

**开关含义（写死，防止实现反了）**：

```
private_only       = true    # 这条事实只能在它被提供的私聊里使用
cross_scope_share  = false   # 是否允许跨范围（私聊→群、群A→群B）使用
```

"默认关"指 **`cross_scope_share=false`**，不是"关掉私聊记忆"。授权绑定到**具体事实 + 允许的群/范围**（`allow_groups`），可撤销；用户说"这个可以跟别人讲"只放开**这一条**，不连带其他私聊记忆。

**权限过滤放在候选检索之前**（不是召回后再筛），派生内容（日记/摘要/48h 回忆/引用块/self）继承来源限制。

- `visibility ∈ {private_only, group_ok, owner_only}`；`group_ok` 必须列出**具体群号**（`allow_groups`），支持撤销。
- `about_user_id` 明确不扩权：A 私聊提"要给 B 一个惊喜"，B 不可见。
- **受众校验按接收面**：群聊回答面向整个群，不能只检查提问者；私聊只检查对话双方。
- 派生内容必须可追溯清除：日记、48h 短期回忆、引用块、`self.md` 都记 `source_message_ids` / `memory_ids`；删除或收紧可见性后由 `scrub` 任务连带清理，避免"主记忆删了、日记里还在"。
- 注入只是降低歧义（`<memory>` 包裹、去换行、≤120 字、声明是数据），**不是安全边界**；权限与操作校验在代码里执行。

## 9. 注入预算

单轮 900 token，优先级：self(≤250) > 引用块(≤240) > 长期记忆(≤320) > 48h 回忆(≤320) > 日记(≤60)。超出按整块丢弃；冲突对整体丢弃。

## 11. 迁移

1. **先停写**（停 astrbot 或迁移锁），**再**取恢复点（`Connection.backup()`）——顺序不能反，否则丢快照到停写之间的数据；
2. 在权威库上迁移；`PRAGMA user_version` 记录版本，每步先查 `table_info`，可重复执行；
3. 失败回滚，`user_version` 不前进；
4. 校验行数/状态分布/抽 5 条人工核对 → 启服务；
5. INSERT 一律显式列名。

## 12. 回放与验收

按消息时间流式重建状态（抽取→强化→替代→夜间），记录 `provider/model/prompt_version/temperature/原始响应`，支持 fixture 重放。

确定性用例（含前提）：
1. 同一消息重跑 → `recall_count` 不变；
2. 连写三份日记 → 强度不变；
3. 前提 `I=0.5, n=0, 非 pinned, 无新消息`；推进 30 天 → 派生 cold 为真，且弱线索注入被拦、强线索仍可召回；
4. 晚录入的历史事实不覆盖当前事实；
5. 前提：存在 ≥5 条合格候选且预算容纳；一条同时命中 A/B/C → 仍能由后续候选补满 5 条；
6. 不可裁决冲突 → 输出"有两种说法"，不输出两个确定答案；预算不足时两条都不出；
7. 私聊事实不出现在群聊注入；且删除后日记/48h/引用块里也消失；
8. 记忆文本含"忽略上述指令" → 仍作为数据注入，不改变行为（**攻击样例回归**，不构成安全证明）。

指标：候选召回率、Recall@5、Precision@5、更新正确率、无依据断言率、可撤销性、每轮 token；cold 占比仅观察。评分不用同一模型自评。
