# 换服务器时的完整恢复步骤

这份文档配合 `D:\dsh-qq\backup\` 里的两类备份使用：

| 文件 | 内容 |
| --- | --- |
| `snapshot-YYYYMMDD-HHMMSS.tar.gz` | 服务器侧全量：9 个插件（含自研 5 个）、`cmd_config.json`、`config/`、`plugin_data/`（记忆库 + 日记 + 自我 + 表情包索引）、`data_v4.db`（聊天原文）、`bin/` 全部脚本、`meta/`（crontab、docker inspect、网络、重建容器的命令） |
| `workspace-YYYYMMDD-HHMM.zip` | 本机工作区源码：`docs/`、`tmp/`（插件源码、迁移脚本、测试）、`panel/`、根目录脚本（backup、tunnel、启动面板） |

服务器每天 04:50 自动打包、保留 10 份；本机每次开机自动拉取、保留 14 份。

---

## 一、新服务器装 Docker

```bash
apt-get update && apt-get install -y docker.io docker-compose-plugin
# 若拉不动镜像，先跑备份包里的 bin/host-bootstrap.sh，它会写入阿里云镜像加速
```

## 二、把备份传上去并解包

在**本机**（PowerShell）：

```powershell
scp -i D:\dsh-qq\key_ssh D:\dsh-qq\backup\snapshot-XXXXXXXX.tar.gz root@新IP:/root/
```

在新服务器：

```bash
mkdir -p /root/restore && tar -xzf /root/snapshot-XXXXXXXX.tar.gz -C /root/restore
ls /root/restore      # 应看到 plugins/ config/ plugin_data/ data/ bin/ meta/ cmd_config.json
```

## 三、跑恢复脚本

```bash
bash /root/restore/bin/restore.sh /root/restore
```

它会：停容器 → 还原 `plugins/`、`config/`、`cmd_config.json`、`plugin_data/` → **再**还原 `data/`（顺序不能反，否则旧的 `memory_system.db` 会盖掉带 WAL 的新库）→ 还原 `/usr/local/bin/*` → 恢复 crontab → 启动容器。

如果新机器上容器还不存在，脚本会提示，此时执行：

```bash
bash /root/restore/meta/restore-docker.sh
```

里面是两条完整的 `docker run`（含端口、卷、`--cap-add=SYS_PTRACE`、`--shm-size` 等）和两条 `docker update`（内存上限）。

## 四、跑主机级加固

```bash
bash /usr/local/bin/host-bootstrap.sh --check   # 先看它要改什么
bash /usr/local/bin/host-bootstrap.sh           # 真跑：4G swap、swappiness、systemd-oomd、
                                                # docker.slice、镜像加速、qqnet、cgroup 上限、6 条 cron
```

这一步是**幂等**的，旧机器上跑也不会重复加 cron。

## 五、验收清单

```bash
docker ps                                    # astrbot / snowluma 都 Up
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:6185   # 200
crontab -l | wc -l                           # 6 行
docker exec astrbot grep -c "适配器已连接" <(docker logs astrbot 2>&1) >/dev/null && echo ok
tail -3 /var/log/health.log                  # 每分钟一条
```

QQ 登录：`snowluma` 的登录态存在卷 `qq-client-config` 里，用 `restore-docker.sh` 重建卷时**不会**自动带上登录态，需要打开 noVNC 重新扫码一次；记忆、日记、自我、配置都不受影响。

## 六、本机需要改的东西（IP 变化时）

| 文件 | 改什么 |
| --- | --- |
| `D:\dsh-qq\backup.ps1` | `$Host_ = 'root@新IP'` |
| `D:\dsh-qq\tunnel-run.cmd` | 末尾的 `root@新IP` |
| `D:\dsh-qq\panel\server.ps1` | `$Host_` 与 `$Key` |
| 计划任务 `dshqq-tunnel` | 重启一次：`schtasks /end /tn dshqq-tunnel` 再 `/run` |

隧道的私钥 `key_ssh`（ACL 已收窄）与公钥 `id_deploy.pub` 需要一起备份到新电脑，否则本机连不上服务器。

## 七、已知的人工步骤（脚本不覆盖）

1. QQ 扫码（卷重建后）。
2. 阿里云安全组：只放 22 端口，其它一律不对外开放（WebUI 全部走 127.0.0.1 + SSH 隧道）。
3. `EULA/PRIVACY` 同意（SnowLuma WebUI 首次登录）。
4. SnowLuma WebUI 密码若被轮换过，恢复后以备份里的 `config/webui.json` 为准（scrypt 哈希，直接可用）；忘了就在服务器上按旧流程重设。
